# CodeClub UVT

All shared knowledge lives in `docs/`. Read `docs/README.md` first, then only the folder relevant to the task.

## Where to look

- **Building or planning the main project (Harness platform):** `docs/project/README.md` is the overview and lists the standing decisions, which must not be re-litigated. Then read the specific subproject file.
- **Anything visual (UI, Figma, posters, slides, social graphics) or any public-facing text:** `docs/visual-identity/`. Use the exact hex values in `colors.md`, fonts in `typography.md`, logo rules in `logo.md`, and wording/tone in `brand.md`.
- **`Games/`:** separate standalone app with its own repo and docs. Don't mix it into `docs/`.

## Rules

- Follow the official Code Club brand as documented. Never invent brand colors, fonts, slogans, or logo variants.
- Don't invent facts about the club (social links, events, contact details). If it isn't in `docs/`, ask the user.
- Don't create empty or placeholder files. Add a doc only when there is real content for it, and list it in the folder's `README.md`.
- Keep relative links between docs working when moving or renaming files.
